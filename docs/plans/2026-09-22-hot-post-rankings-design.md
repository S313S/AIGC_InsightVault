# 热门原帖与分类热榜设计

## 目标

恢复主页过去“先看热门原帖、再看分类榜单”的浏览节奏，同时修复“查看全部”只显示全局最新快照中少量社交帖子的问题。

## 页面结构

主页由上到下固定为：

1. 状态概览：采集总量、最近采集时间、页面同步状态。
2. 热门原帖：默认展示 6 张有图片、有原文链接的社交帖子卡片。
3. 分类热榜：按真实标签归类并按热度排序，每类展示前三条。
4. AI 话题雷达：保留“值得写、值得沉淀、突发”三个编辑视角。
5. 事实证据：GitHub 与官方来源独立展示，用于核验话题，不混入原帖数量与热度榜。

## 数据口径

- 首页读取完整的保留快照数据，不再先截取 60 行后再筛选。
- 社交原帖按平台分别选择“该平台最近一次成功出现的快照”，再按标准化原文链接去重。
- 当前快照里的 GitHub 与 Official 证据继续使用全局最新快照，避免把历史版本公告重复带回主页。
- 平台数据较旧时继续展示，但必须标注该平台的最后采集时间，不能伪装成刚采集。
- “查看全部原帖”只展示完整社交原帖池；事实证据在独立区域展示，并提供来源链接。
- 分类榜单只接受真正匹配分类标签或文本信号的帖子；分类不足时显示实际数量，不用无关帖子补位。

## 分类规则

首批支持四类：

- Vibe Coding
- AI 工具
- Image Gen
- Video Gen

分类依据统一的标签和有限关键词匹配。一个原帖可以进入多个真实匹配分类；同一分类内按点赞数、收藏数、发布时间和稳定 ID 排序。没有数据的分类不渲染，避免空榜和错误归类。

## 交互与可访问性

- 热门卡片整卡可点击，并只打开安全的 HTTP/HTTPS 原文链接。
- “查看全部原帖”使用现有可访问对话框，保留焦点圈定、Escape 关闭和背景滚动锁定。
- 分类榜单项使用按钮语义，支持键盘访问。
- 小红书缺少 `xsec_token` 时继续显示提醒与修复入口。

## 验收标准

- 首屏状态概览之后立即看到热门原帖卡片，AI 话题雷达不再位于原帖之前。
- 当前线上数据应能同时恢复 Twitter 最近快照和小红书最近成功快照，且页面明确显示各平台数据时间。
- “查看全部原帖”的数量与实际渲染卡片数量一致，滚动到底可看到全部。
- GitHub/官方证据不占原帖卡位，也不进入社交热度榜。
- 分类榜单无跨分类兜底污染，所有条目均能打开原文。
- 自动化测试、生产构建、真实浏览器桌面视口和窄视口验收全部通过后，才允许合并到 `main` 并推送。
